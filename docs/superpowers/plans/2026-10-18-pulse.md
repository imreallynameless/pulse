# Pulse Implementation Plan

> Implement inline, milestone by milestone. The user has authorized starting implementation.

**Goal:** Verify direct live Bluetooth readings, then deliver a reusable website embed.
**Architecture:** Local Chrome receiver first; authenticated push relay and read-only widget after hardware validation.
**Tech Stack:** Browser JavaScript modules, Node 22+, node:test; no runtime dependencies for the tester.
**Spec:** ../specs/2026-10-18-pulse.md

## Constraints and review focus
No readings published during the test. Reject malformed BLE packets. Distinguish unsupported contact from lost contact. Preserve repeated values. Expire stale readings. Stop previous sessions before reconnecting. Diagnostics describe receipt timing, never physiological latency.

### Task 1: Local tester
- [x] Write failing tests for 8/16-bit BPM, optional contact/energy/RR fields, malformed payloads, timing summaries, and stale/disconnected state.
- [x] Implement web/heart-rate.mjs exports decodeHeartRate(DataView), summarizeIntervals(number[]), readingState(boolean, number|null, number).
- [x] Implement web/index.html, web/app.mjs, web/style.css and loopback-only server.mjs. UI connects via heart_rate / heart_rate_measurement notifications and supports disconnect, reconnect and explicit local export.
- [x] Run npm test and smoke-test server and browser UI.
- [x] Add MIT, README, CONTRIBUTING and CI; publish clean source repo without diagnostics.
- [x] Connect real Fitbit Air, observe readings, document measured cadence and limits (initial short test; long soak pending).

### Task 2: Relay and embed
- [x] Write integration tests for publisher authorization, read-only viewers, duplicate values, stale expiry, disconnects and latest-only recovery.
- [x] Implement relay plus iframe with live/offline status, start/stop broadcast and copyable embed.
- [x] Verify real Fitbit feed through a cross-origin local iframe and offline on stop; feed isolation tested. Precise receiver-to-render and public-network latency remain unmeasured.
- [x] Document deployment, forks and embedding. Public hosting and portfolio insertion remain the next deployment step; no host/domain has been selected.
